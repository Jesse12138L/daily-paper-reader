## 摘要
机器人应能通过实验学习陌生物体的行为和相互作用，然后利用这些知识进行规划。它不必从零开始：物理引擎提供了运动与接触的知识，但可能遗漏整个机制，例如胶水固化、水加热或风。我们提出 EMPIRIC，一个学习残差世界模型的智能体：一个物理引擎，并针对缺失机制扩展了代码。学到的程序可以引入新的力、约束和隐藏状态，而贝叶斯推断从带噪观测中估计它们的参数和状态。由此得到的模型使智能体能够预测动作结果、选择信息量大的实验，并在预测失败时修正其假设。在五个模拟领域中，EMPIRIC 学习到可解释、可复用的模型，并且比所有三个基线用更少的环境交互解决了更多任务。在实体机器人上，它学习风力与多米诺骨牌质量以完成一项操作任务。网站与代码：https://yichao-liang.github.io/empiric

## Abstract
A robot should be able to learn through experiments how unfamiliar objects behave and interact, then plan with that knowledge. It need not start from scratch: physics engines supply knowledge of motion and contact, but can omit entire mechanisms, such as glue curing, water heating, or wind. We present EMPIRIC, an agent that learns a residual world model: a physics engine extended with code for the missing mechanisms. The learned programs can introduce new forces, constraints, and hidden state, and Bayesian inference estimates their parameters and states from noisy observations. The resulting model lets the agent predict the outcomes of actions, choose informative experiments, and revise its hypotheses when predictions fail. Across five simulated domains, EMPIRIC learns interpretable, reusable models, and solves more tasks with fewer environment interactions than all three baselines. On a physical robot, it learns wind forces and domino masses to solve a manipulation task. Website and code: https://yichao-liang.github.io/empiric

## 1. 核心问题与研究动机

- **背景**：机器人进入新家庭环境时会遇到大量未见过的人造物与材料——胶水、电风扇、保险箱、炉子、橡皮泥、悬浮板、扭蛋机、断路器板等。物理引擎（如 PyBullet）可提供刚体运动与接触的通用知识，但会**整体缺失某些机制**：胶水固化、水加热、气流推动等。
- **关键缺口**：Real-to-sim 类方法能重建物体几何与铰接结构，但"重建几何"本身并不告诉机器人"开风扇会产生气流推动物体"或"胶水接触一段时间后会粘合"。即：**结构恢复 ≠ 机制识别**。
- **参数与隐状态问题**：即使机制已知，机器人仍需推断特定风扇的风力大小、特定胶水的固化时间；这些参数往往不可直接观测（如关节是否粘住取决于两块的接触时长），且观测带噪、部分可观测。
- **研究问题**：在给定刚体物理先验的前提下，机器人如何用少量实验快速学得缺失机制的世界模型，并在对参数与隐状态存在不确定性时进行规划？
- **整体含义**：论文提出以"可执行代码残差"形式为物理引擎补充缺失机制，把"写机制"与"估参数"分离，从而在交互效率与任务成功率上同时获益。

## 2. 方法论

### 2.1 核心思想

- **残差世界模型（Residual World Model）**：机器人从一个通用刚体物理基础模拟器出发，编写 Python 程序 `P`（子类化 `BaseSimulator`）来补充缺失机制。程序可**施加新力、施加约束、维护隐藏循环状态**（如胶水固化进度、水体积/温度）。
- "残差"并非仅指加性修正，而是泛指可执行扩展。
- 学习循环交替进行：**写/改程序 P → 拟合参数 θ → 在模拟中排练计划 → 执行/实验 → 预测失败则修正 P**。

### 2.2 表示与状态分解

- 模型状态 `x = (x_base, x_res)`：`x_base` 为引擎可恢复状态（几何、姿态、附件），`x_res` 为程序声明的循环状态（引擎不追踪的量）。
- 单步流程：先跑基础物理 `x̄_base,t+1 = F̂_θbase(x_base,t, a_t)`；再由观测驱动更新循环状态 `x_res,t+1 = g_θ(h(x̄_base,t+1), x_res,t, a_t)`；最后执行动力学钩子 `x_base,t+1 = U_θ(x̄_base,t+1, x_res,t+1)`（施加力/约束/更新量）。
- 关键设计：循环状态更新**只读可观测特征**（`update_model_state` 为纯函数，无引擎访问），因此同一更新函数可同时用于模拟与真实观测历史，且不依赖特权状态。

### 2.3 参数与状态推断（贝叶斯）

- 信念近似（式 2）：
  `p(θ, x_t | D, H_t) ≈ q(θ) · q(x_base,t | H_t) · δ_{G_θ(H_t)}(x_res,t)`
  - `q(θ)`：参数后验，平均场近似（各参数独立）。
  - `q(x_base,t | H_t)`：仅由观测条件化的状态后验（modular/cut，避免动力学误差污染位姿估计），用贝叶斯在线变点检测对"静止帧"求平均。
  - 第三项为点质量：每个参数抽样配对其自身蕴含的循环状态（短固化阈值下两方块判为粘合，长阈值下不粘合）。
- **重放损失**：把记录轨迹分段重放，计算标准化平方误差（按传感器噪声 + 5% 特征范围标准化，角度按圆处理，Huber 损失抑制离群），末态加权 25 倍；某段即使最优重放误差仍超阈值则判为"缺失机制"证据。
- **广义后验**（式 12）：`p(θ|D) ∝ p₀(θ)·exp(−E(θ)/(2λ))`，温度 `λ = max(1, E_min/N)`，当程序无法拟合到噪声尺度内时自动放宽信念，避免过度自信。

### 2.4 规划与信息寻求

- **任务规划**（式 3）：从 K 个联合抽样 `(θ(i), x_t(i))` 出发排练候选技能序列 ω，取成功概率最大者：
  `Pr̂(ω) = (1/K) Σ_i R(τ_{θ(i)}(x_t(i), ω))`，所有候选共享同一组抽样以消除抽样噪声。仿真域 K=16，真机 K=24。
- **信息寻求**（式 4）：用谓词（谓词是观测的固定函数）估计参数与谓词读数的互信息：
  `I_j(ω) = H((1/K)Σ_i r_ij) − (1/K)Σ_i H(r_ij)`，该量下界于全观测的信息量。智能体按平均谓词信息对实验排序，并权衡环境步代价。
- **谓词 Φ**：用 Python 写的观测特征分类器（如 `Attached(a,b)`），承担三种角色：校验技能预期结果、作为 Wait 的目标条件、作为实验子目标以度量信息量。
- 计划参数（放置位置、推动时长等）由 `sim.refine` 做回溯搜索并在共享抽样上打分。

### 2.5 执行监控与模型修正

- 每个技能标注预期谓词；若某谓词在 K 个联合抽样中成立比例 < 1/2（对称代价下的贝叶斯决策），则判为未达成，默认中止技能序列并把控制权交回智能体。
- 出现偏差后，智能体可：改计划、做实验、更新参数信念、或编辑模拟器程序。
- 若"任何参数取值都无法解释某观测效应"，则判定需增加/修改机制（例如加入"接触时长累积 → 超过阈值成键"的循环状态机制）。
- 每次环境步都计入预算（无论用于任务还是实验）；沙箱内的模拟不计步。

## 3. 实验设计

- **仿真平台**：PyBullet 桌面操作，五个域：
  1. **Domino**：排列蓝色骨牌使绿色推倒红色目标，姿态带噪、摩擦未知（测试需 90° 转向级联）。
  2. **Bridge**：用胶水把方块粘成桥，姿态带噪、粘合与固化进度隐藏。
  3. **Balloons**：释放气球使箱子停在目标高度带；升力与天花板爆裂需学习，释放不可逆。
  4. **Boil**：注水并加热到目标温度不溢出；基础模拟器不会注水/加热。
  5. **Fan**：开关风扇把球停在目标；需学气流与阻力。
- **真实机器人**：Franka Emika Panda 七自由度臂 + 平行夹爪 + ZED 2i 立体相机，真实 **Fan–Domino** 域：风力未知、两块多米诺质量未知；训练目标用一次气流把轻块吹进目标贴片，测试目标贴片下移更远且必须用重块完成。
- **评测协议（continual）**：每次 run 含 M 个训练任务 + N 个测试任务（Balloons 为 2 个训练任务），**只有全部任务解出才算 run 成功**；训练允许 reset，测试不允许；所有任务共享环境步预算（Domino/Boil/Fan 10,000；Balloons 15,000；Bridge 20,000）；提前失败则剩余任务计为未解。每域每智能体 5 个种子。
- **对比方法（7 个智能体，均用 Claude Opus 5 high effort、同一技能库/接口/预算）**：
  - 1) **Direct agent**（仿 CaP-X 多模态 M2）：无模拟器。
  - 2) **Direct + scene**（仿 SimFoundry）：给场景资产与引擎代码，可自行模拟。
  - 3) **Standalone sim.**（仿 WorldCoder）：自行写可执行转移模型，无基础模拟器。
  - 4) **Oracle dynamics**：直接给真值动力学程序与参数，但仍只有噪声观测、无隐藏状态。
  - 5) **No harness fitting**（消融）：去掉拟合参数信念，用先验抽样排练。
  - 6) **No explicit uncertainty**（消融）：从原始噪声观测 + 点参数估计规划（同时去掉噪声尺度声明、状态平滑、参数不确定性支持）。
- **指标**：整 run 成功率、成功率–步数预算曲线（式 5）、均值步数；用双侧 Fisher 精确检验比较。

## 5. 实验数量与充分性

- **规模**：7 个智能体 × 5 个仿真域 × 5 个种子 = **175 次仿真 run**（每格 25 次为 EMPIRIC 的 5 种子 × 5 域）。真机为**单次 run**（1 个训练任务 + 1 个测试任务）。
- **消融**：两组消融（No harness fitting、No explicit uncertainty），覆盖全部 5 个域 × 5 种子。
- **公平性设计**：
  - 所有智能体使用同一 LLM、同一任务接口、同一技能库、同一步预算、同一噪声设置，比较条件较受控。
  - Oracle dynamics 作为上界参照，但注意它也没有完美状态估计与控制器，因此"正确动力学 ≠ 更高效率"的结论有依据。
  - 失败 run 可能提前结束，作者明确指出均值步数不具信息量，转而使用成功率–预算曲线，这一处理较为严谨。
- **充分性评价**：
  - 仿真部分覆盖 5 个不同机制类型（接触/粘合/浮力爆裂/热与流体/气流），维度较全面；统计检验（p ≤ 0.002）支持主要结论。
  - **但真机仅 1 次 run、1 个台面、1 类任务**，作者自己承认"one run on one bench"，统计意义有限。
  - 消融中的 No explicit uncertainty **捆绑移除多项能力**（噪声尺度、状态平滑、参数不确定性），无法隔离单一因素，论文也如实说明。
  - 缺少对信念校准度的量化测试（论文明确指出未做留出集校准评估），也未提供每个域"缺失机制"数量的系统性扫描。

## 6. 主要结论与发现

- **Q1 对比基线**：EMPIRIC **解出全部 25/25 仿真 run**；Direct agent 16/25、Direct + scene 14/25、Standalone sim. 16/25（各差异双侧 Fisher 检验 p ≤ 0.002）。步数上在 5 域中 4 域少于 Direct agent 与 Direct + scene，5 域全部少于 Standalone sim.；每个域中 EMPIRIC 以更少步数达到 60% 解出率。
- **Q2 与 Oracle 对比**：EMPIRIC 与 Oracle dynamics 同为 25/25；步数在 Domino/Bridge/Balloons 多 12–18%，Boil 多 74%（部分反映学习机制的成本），Fan 反而少 8%。说明"正确的动力学不保证交互效率"，而"学到的模型不必处处精确也能有用"（Bridge 中位姿预测有误，但仍可用于筛选放置并实测倾斜来选择释放高度）。
- **Q3 消融**：No harness fitting 降至 20/25，No explicit uncertainty 降至 21/25；两者在 Boil/Fan 有时比 EMPIRIC 更省步（因机制近似恒定、保守目标、对抗式制动降低了不确定性敏感度），但在 **Balloons 这类不可逆动作场景**显著落后（EMPIRIC 5/5 vs 2/5 与 3/5，所有失败均为天花板爆裂）。结论：**参数推断与显式不确定性在动作不可撤销时最关键**。
- **Q4 真机**：从两次单块吹风实验（绿块不动、灰块倒下并滑移 12.1 cm）学到风力模型（按钮按住时

按钮按住时持续产生横向气流、释放后气流立即消失），并据此推断两块多米诺的相对质量与所需吹风时长。规划阶段，机器人用一次较长的气流把重块推入下移后的目标贴片；执行时以谓词监控（如"目标块是否位于贴片内"），成功后结束 run。
  - 该实验的主要意义不在于统计功效，而在于证明**同一套"写机制 + 估参数 + 显式不确定性 + 谓词监控"的流程可以跨过 sim-to-real 边界**：机器人面对的是真实相机噪声、真实夹爪误差与真实未知风力，仍能在共享步数预算内完成训练与测试两个任务。
  - 作者同时坦承：真机结果仅为**单次 run、单一台面、单一任务对**，属于可行性验证（proof-of-concept），不能据此宣称方法在真机上的普遍有效性。
- **总体结论**：
  1. **机制与参数应当分离**：把"缺失机制"表达为可执行程序、把"环境特异性"留给贝叶斯参数信念，使同一套机制代码能在不同风扇/胶水/气球上复用。
  2. **不完美的模型仍然有用**：EMPIRIC 在 Bridge 中位姿预测存在偏差、在 Fan 中动力学近似粗糙，但配合显式不确定性与谓词级监控，仍可选出鲁棒的计划，这解释了它为何能在部分域逼近甚至超过 Oracle dynamics。
  3. **显式不确定性的价值与动作可逆性相关**：在可重置、可重试、机制近似恒定的域（Boil、Fan），不确定性建模带来的收益有限甚至略显保守；在**不可撤销动作**（气球释放、爆裂）场景则是决定性的。
  4. **拟合是"机制充分性"的判据**：当任何参数取值都无法把记录轨迹重放到噪声尺度内时，该证据被解释为"机制缺失"而非"参数不好"，从而触发程序编辑——这是该框架区别于纯参数辨识的关键机制。

## 7. 局限与未来工作

- **真机证据薄弱**：仅 1 次 run、1 个台面、1 类任务，缺少多任务、多次重复与不同初始条件的统计验证。
- **机制表达依赖 LLM 的编程能力**：残差程序由语言模型撰写，若机制涉及复杂连续场（如真实流体、软体大变形、多体摩擦），"写一个可执行残差"本身可能非常困难或不可行；论文未系统测试机制复杂度的上限。
- **未做信念校准评估**：论文明确指出没有在留出集上量化后验的校准度（如覆盖率、可靠性图），因此"不确定性建模有效"主要靠端到端任务成功率间接支持。
- **消融不可分解**：No explicit uncertainty 同时移除了噪声尺度声明、状态平滑与参数不确定性支持，无法定位到底是哪一项贡献最大。
- **预算与规模**：每域仅 5 个种子、任务数有限；共享步数预算下"提前失败即剩余任务全记为未解"的设定较为严苛，可能放大了方差。
- **算力披露不足**：未给出 GPU/CPU 型号、并行度与总成本，仅报告 LLM 轮次、rollout 数与墙钟时间，复现成本难以精确估计。
- **可能的扩展方向**（论文隐含）：自动检测机制缺失的更细粒度信号、机制库的跨任务迁移与复用、把谓词设计本身也交给模型学习、以及在更多真实家庭场景（多物体、多机制耦合）中验证。

## 8. 贡献与启示

- **方法层面**：提出"可执行残差世界模型"这一具体表示，把 Real-to-sim 的"结构恢复"推进到"机制恢复"，并给出与之配套的参数推断（平均场 + 广义后验 + 重放损失）、信息寻求（谓词互信息下界）与执行监控（谓词多数表决中止）三件套。
- **工程层面**：整个系统在统一技能库、统一 LLM、统一预算下与 6 个基线对比，且把每个基线的设计对应到已有工作（CaP-X、SimFoundry、WorldCoder），使比较更具可解释性。
- **实证层面**：25/25 的仿真整 run 成功率、对 Oracle dynamics 的效率对照、以及不可逆动作场景下消融的显著差异，共同支撑"机制学习 + 显式不确定性"的核心主张。
- **对后续研究的启示**：机器人在开放环境中的世界模型或许不需要"一次性建对"，而应是一个**可编辑、可拟合、可监控**的程序化对象；"什么时候该加机制、什么时候只需调参数"这一判据（拟合残差是否超出噪声尺度）比单纯追求模型精度更贴近实际部署需求。
