## 摘要
通用视觉语言模型为零样本机器人控制提供了一种有前景的方法：GPT-6 Astra 在开放式以及以语言或图像为条件的操作方面表现优异，但在高精度和长时程任务上仍然明显较弱。我们提出 RoboICL，一个上下文机器人控制框架，无需机器人特定的参数更新，也无需学习得到的 VLA，即可缩小这些差距。RoboICL 将演示上下文与交互记忆分离：前者在可用时提供录制的示例，后者累积模型自身的动作与观察到的结果。两者均使用共享的观测—动作—回执—观测语法。为在任务各阶段保留经验，RoboICL 将采样得到的演示块与有界锚定记忆相结合。固定锚点使较早的 rollout 交互仍可用于上下文学习，而最新交互则支持即时错误纠正。在 30 个 RoboDojo 任务上，对 Open 使用零样本，在其他任务上使用一个演示，RoboICL 在每个类别中都比官方零样本 GPT-6 Astra 提高了 20–27 个进度分数点。它在 Memory 和 Open 上领先于排行榜基线，性能与最强的 Precision 基线相当，并在 Long-Horizon 上保持竞争力。其 30 任务 Overall 得分为 50.64，而最强基线为 33.68。在另一个十任务子集上，RoboICL 得分为 60.60，与 π_{0.5} + GPT-6 Astra 混合方法相差不到 2.00 分。在三个真实机器人任务上，平均进度从零样本的 14.45 提升到单样本的 63.33 和三样本的 78.89。在两个开发任务上，可选的 Jev 门控动作复用将 GPT-6 Astra 调用减少 33–48%。代码可在 https://github.com/Mosi-AI/RoboICL 获取。

## Abstract
General-purpose vision-language models offer a promising way to zero-shot robot control: \gptastra{} excels at open-ended and language- or image-conditioned manipulation but remains substantially weaker on high-precision and long-horizon tasks. We introduce \emph{RoboICL}, an in-context robot-control framework that narrows these gaps without robot-specific parameter updates or a learned VLA. RoboICL separates \emph{demonstration context}, which provides recorded examples when available, from \emph{interaction memory}, which accumulates the model's own actions and observed outcomes. Both use a shared observation--action--receipt--observation grammar. To preserve experience across task stages, RoboICL combines sampled demonstration blocks with bounded anchored memory. Fixed anchors keep earlier rollout interactions available for in-context learning, while the latest interaction supports immediate error correction. Across 30 RoboDojo tasks, using zero shot for Open and one demonstration elsewhere, RoboICL improves on official zero-shot \gptastra{} by 20--27 progress-score points in every category. It leads the leaderboard baselines on Memory and Open, achieves comparable performance to the strongest Precision baseline, and remains competitive on Long-Horizon. Its 30-task Overall score is 50.64, versus 33.68 for the strongest baseline. On a separate ten-task subset, RoboICL scores 60.60, within 2.00 points of the $π_{0.5}$ + \gptastra{} hybrid approach. On three real-robot tasks, mean progress rises from 14.45 at zero shot to 63.33 at one shot and 78.89 at three shots. On two development tasks, optional Jev-gated action reuse reduces \gptastra{} calls by 33--48\%. Code is available at \href{https://github.com/Mosi-AI/RoboICL}{https://github.com/Mosi-AI/RoboICL}.

## 2. 方法论

### 2.1 核心思想

- 将上下文分为两类：
  - **演示上下文（Demonstration Context）**：固定不变的专家演示，提供任务程序性知识。
  - **交互记忆（Interaction Memory）**：随执行动态更新，记录模型自身动作、回执与观察结果。
- 两者共享同一套**观测—动作—回执—观测**语法，使模型在演示与在线经验中看到一致的“前态—动作—后态”模式。
- 模型参数 \(\theta\) 完全冻结，动作仅由指令、当前状态和保留上下文条件生成。

### 2.2 请求与动作生成流程

- 请求构造：  
  \(Q_t = \text{Serialize}(g, D_K, M_t, o_t, z_t)\)  
  其中 \(g\) 为任务指令，\(D_K\) 为演示上下文，\(M_t\) 为交互记忆，\((o_t, z_t)\) 为当前视觉观测与本体状态。
- 动作预测：  
  \(A_t \sim \pi_\theta(\cdot \mid Q_t)\)，且 \(A_t \in \mathbb{R}^{H \times d_a}\)。
- 机器人控制 harness 直接调用多模态 API，只暴露一个 `act` 函数工具，接收连续动作块与简短执行说明；不使用外部技能库或通用 coding-agent 运行时。

### 2.3 动作表示与执行

- 在 RoboDojo 双臂平台中，\(d_a = 14\)：每条动作包含左右臂各 7 维。
- 单臂动作为：  
  \(a_{t,i} = [\Delta p^L_{t,i}, \Delta r^L_{t,i}, u^L_{t,i}, \Delta p^R_{t,i}, \Delta r^R_{t,i}, u^R_{t,i}]\)  
  其中 \(\Delta p, \Delta r \in \mathbb{R}^3\) 为世界坐标系下的平移与旋转向量增量，\(u \in [0,1]\) 为绝对归一化夹爪目标。
- 控制参考点为各臂 link-6 原点，而非指尖中点或标定 TCP。
- 确定性代码负责形状/边界校验、逆运动学求解，并执行可行动作前缀；RoboDojo 控制频率为 25 Hz。

### 2.4 共享交互语法与回执

- 每次交互记录为：  
  \(c_j = ((o_j, z_j), A_j, r_j, (o_{j+1}, z_{j+1}))\)
- 在交互记忆中，\(r_j\) 为执行回执，报告预测、派发、实际执行步数、执行区间、目标跟踪与控制器中断。
- 在演示上下文中，\(r_j\) 为合成回执，包含源区间、动作计数与索引、动作账本哈希、最后目标、跟踪残差与采样端点索引。
- 只有正长度已执行转移会提交到锚定记忆；被拒绝且未执行命令的交互留在请求尾部，允许从同一状态纠错。

### 2.5 有界锚定记忆

- 设 episode 最大环境步数为 \(T\)，记忆槽为 \(B\)。
- 前 \(B-1\) 个槽保留固定时间锚点，目标为 \(\tau_i = \lfloor iT/B \rfloor\)，最后一个槽保留最新交互。
- 显式插入 `<TRAJECTORY_GAP>` 标记被省略区间，避免分离观测被误读为连续。
- 演示上下文同样按非重叠块采样：每个演示保留 \(J\) 个块，总预算为 \(C = KJ + B\)。
- 主实验设置：
  - 零样本：\(K=0, B=25\)。
  - 单样本：\(K=1, J=B=12\)，最多约 48 张端点图，个别任务保留终端观测后最多 49 张。
  - 三样本缩放研究：\(K=3, J=5, B=5\)，最多 40 张端点图。
- API 配置限制每次请求最多 50 张图像，因此演示覆盖与交互记忆需联合分配。

### 2.6 效率设计

- **稳定前缀缓存复用**：任务指令、演示消息、固定相机标定构成固定前缀；已完成锚点与关闭的 gap 不变；最新非锚点交互与待纠正内容构成可变后缀。
- **基于步数上限的动作时域**：
  - \(T \le 400\)：\(H=5\)
  - \(400 < T \le 700\)：\(H=10\)
  - \(700 < T \le 1100\)：\(H=15\)
  - \(1100 < T \le 1600\)：\(H=20\)
  - \(T > 1600\)：\(H=25\)
- **Jev 门控动作复用**：可选地让 Jev 基于结构化状态与问题判断是否复用 GPT-6 Astra 已预测的动作后缀，从而减少模型调用。
